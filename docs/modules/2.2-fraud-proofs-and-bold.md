# 2.2 — Fraud Proofs & BoLD

> **TL;DR:** An optimistic rollup assumes posted state is correct unless someone proves otherwise. Validators post **assertions** about the L2 state to L1 with a **bond**; if two assertions disagree, an **interactive fraud proof** narrows the disagreement down to one execution step that Ethereum checks. **BoLD** upgrades this so *anyone* can validate (permissionless) and every dispute resolves in a **fixed, bounded time** (~6.4 days) no matter how many attackers — fixing the old "delay attack" weakness.

## Optimistic Rollup Security Model (recap)

- "Optimistic" = the rollup **assumes assertions are valid by default** and only checks them if challenged. No proof is posted on the happy path (unlike ZK, which proves every batch).
- Security rests on the **one honest party** assumption: because the L2 state transition is deterministic, a single honest validator who watches L1 can always prove a bad assertion wrong.
- The catch: this only works if honest parties can actually *participate* and disputes actually *resolve*. That's exactly what the old protocol got wrong and BoLD fixes.

## Assertions, Validators, Bonds

What actually gets posted to Ethereum:

- **Assertion** — a claim about the Arbitrum chain's state at a checkpoint (block hashes + a history commitment). This is the thing that can be challenged.
- **Validators** — nodes that post assertions and/or challenge wrong ones. They re-run the state transition and compare against what's on L1.
- **Bonds** — posting an assertion requires locking a large bond (**3,600 ETH on Arbitrum One**); challenge moves require smaller bonds. If unchallenged, an assertion confirms after the challenge window (~**6.4 days**).
- **Slashing / refunds** — the loser of a dispute **forfeits their bond** (to the Arbitrum DAO treasury); honest parties get theirs back. The large bond is what makes attacks expensive.

## BoLD: Permissionless, Time-Bounded Fraud Proofs

**BoLD = Bounded Liquidity Delay.** Two big changes over the old challenge protocol:

**1. Permissionless.** Before, only an **allowlisted** set of validators could challenge. Now *anyone* who posts a bond can propose or dispute assertions — no permission needed. (Bonding pools let people crowdsource the large bond.)

**2. Bounded resolution time (the key property).** The old protocol was **1-vs-1**: the honest party fought challengers one at a time, so N attackers could **delay** confirmation by opening dispute after dispute ("delay attack"). BoLD is **all-vs-all**: the honest party defends against *every* adversary **in parallel**, so a dispute resolves in a **fixed ~6.4 days regardless of how many attackers** show up.

How a dispute actually resolves (interactive fraud proof):

1. Two assertions **fork** (disagree) → a challenge opens as a graph of Merkle-committed histories.
2. **Bisection** — repeated binary search halves the disputed range, drilling down through levels: **blocks → BigSteps → SmallSteps** until the disagreement is a **single WASM execution step**.
3. **One-step proof** — that one step is verified on Ethereum by a **mini WASM VM deployed as an L1 contract (WAVM)**. It's impossible to fake a valid step, so the honest party wins.

The one-honest-party guarantee holds: bonded to the correct state, a single honest validator **always prevails**, now in bounded time and open to anyone.
