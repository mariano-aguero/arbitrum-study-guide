# 3.3 — Stylus Rust SDK Essentials

> **TL;DR:** A Stylus contract is a Rust struct: **`sol_storage!`** defines state that lives in **the same slot layout as Solidity**, **`#[public]`** exposes methods (mutability inferred from `&self` vs `&mut self`), and **`#[entrypoint]`** marks the contract the router dispatches to. Cross-contract calls go through typed **`sol_interface!`** bindings; composition is **`#[inherit]` + `#[borrow]`** instead of Solidity inheritance. Everything is built on **Alloy** primitives (`U256`, `Address`), so the contract speaks the same types as the rest of the Rust Ethereum stack.

## Anatomy of a Contract

```rust
sol_storage! {
    #[entrypoint]
    pub struct Counter {
        uint256 number;
        mapping(address => uint256) balances;
    }
}

#[public]
impl Counter {
    pub fn number(&self) -> U256 { self.number.get() }          // view
    pub fn increment(&mut self) { self.number.set(self.number.get() + U256::from(1)); }
    #[payable]
    pub fn deposit(&mut self) { /* msg value available */ }
}
```

| Macro / attribute | Role |
|---|---|
| `sol_storage!` | Declares state with **Solidity syntax** → identical EVM slot layout |
| `#[entrypoint]` | Marks the top-level contract struct (required by `cargo stylus check`) |
| `#[public]` | Exposes methods in the ABI; `&self` = **view**, `&mut self` = **write**, neither = **pure** |
| `#[payable]` | Lets a method (or the constructor) receive ETH |
| `#[constructor]` | One-time init, runs atomically with deploy+activate; use `tx_origin()` for the deployer (deploys go through a factory, so `msg_sender()` is the factory) |
| `sol_interface!` | Generates typed Rust bindings for calling external contracts |

## Storage: Solidity-Equivalent Slots

- Each field maps to a typed accessor: `StorageU256`, `StorageAddress`, `StorageMap`, `StorageVec`, `StorageString`… — read with `.get()`, write with `.set()`, index maps with `.getter(key)` / `.setter(key)`.
- **The layout is byte-for-byte Solidity's**: slot packing, mapping hashing, everything. That's what makes a Stylus contract a drop-in citizen — a proxy can delegate to it, and Solidity tooling understands its storage.
- Reads/writes go through a **storage cache**: repeated access to the same variable is "virtually free"; the SDK flushes the cache automatically before any external call so values can't go stale across reentry.
- Collections hand out `StorageGuard`/`StorageGuardMut` — the **borrow checker** enforces you can't hold two mutable handles into state, killing a whole class of aliasing bugs.
- `#[derive(Erase)]` lets you clear fields and collect storage refunds.

## Ether, Calls, Errors

- **Blockchain context** comes from the host: `self.vm().msg_sender()`, `msg_value()`, `block_timestamp()`, `tx_origin()`.
- **Sending ether:** `transfer_eth(to, amount)`, or attach value to a call with the `Call` builder (`Call::new_in(self).value(amount)`).
- **Calling contracts:** declare the target with `sol_interface!` and invoke it — under the hood `call()`, `static_call()` or `delegate_call()`; `RawCall` exists for untyped calls but is `unsafe` (manual cache management).
- **Errors & reverts:** methods return `Result<T, E>` where the error derives `SolidityError` — it ABI-encodes to a normal Solidity custom error, so EVM callers can decode it. A `panic!` also reverts, but with no error data; prefer typed errors.
- **Events:** defined with Alloy's `sol!` and emitted with `log(self.vm(), MyEvent { .. })`.

## Inheritance: `#[inherit]` + `#[borrow]`

Solidity's `is` doesn't exist in Rust, so the SDK composes instead:

- Nest the parent as a field and mark it `#[borrow]` — the SDK implements `Borrow<Parent>` so parent methods can run on your struct.
- Add `#[inherit(Parent)]` on the `#[public]` impl — unmatched calls route to the parent by **depth-first search** (first match wins, like Solidity's C3-ish lookup).
- This is how OpenZeppelin's Stylus library works: your token embeds `Erc20` and inherits its public interface, then overrides or extends what it needs.

## Alloy Primitives & the Rust Ethereum Stack

- The SDK's types are **[Alloy](https://alloy.rs)** types: `U256`, `I256`, `Address`, `B256`, plus the `sol!` macro for Solidity type definitions.
- Same types used by Rust tooling offchain (Alloy providers, Foundry internals) → you can **share one crate** of types/logic between the contract and a Rust backend, compiled `no_std` onchain and `std` offchain.
- SDK v0.10.x ships six crates — you touch `stylus-sdk` (and its prelude) and `cargo-stylus`; `stylus-test` provides `TestVM` so `cargo test` runs contract logic natively, no chain needed. Audited by OpenZeppelin (2024, follow-ups in 2025).
