# 3.4 — Local Dev & First Deploy

> **TL;DR:** The whole loop is **`cargo stylus new` → `check` → `deploy`** against a local **Nitro devnode** (one Docker script, prefunded account included). `check` compiles to WASM and simulates activation without spending gas; `deploy` sends **two transactions** — deployment (compressed WASM onchain) and **activation** (native compilation via the ArbWasm precompile), the extra step Solidity doesn't have. Same commands with a different `--endpoint` take you from localhost to **Arbitrum Sepolia**.

## Setup: Toolchain + Devnode

```shell
# Rust ≥ 1.91 with the WASM target
rustup target add wasm32-unknown-unknown

# the CLI (needs Docker for reproducible builds; Foundry's cast to interact)
cargo install --force cargo-stylus

# local chain: Nitro in --dev mode
git clone https://github.com/OffchainLabs/nitro-devnode.git
cd nitro-devnode && ./run-dev-node.sh
```

The devnode exposes RPC at **`http://localhost:8547`** and ships a **prefunded dev account** (`0x3f1E…2d0E`, private key published in the docs — test-only, obviously). The script auto-deploys the Stylus cache manager and takes chain ownership, so Stylus works out of the box. It's the lightweight cousin of the full `nitro-testnode` — no L1, no bridge, just a fast L2 to iterate against.

## The `cargo stylus` Loop

| Command | What it does |
|---|---|
| `cargo stylus new my-contract` | Scaffolds a project (a Rust **Counter** template) |
| `cargo stylus check` | Compiles to WASM, Brotli-compresses, validates exports/imports/size, **simulates activation via `eth_call`** — catches problems without spending gas |
| `cargo stylus export-abi` | Prints the **Solidity interface** of your contract — hand it to any EVM tooling |
| `cargo stylus deploy` | Deployment tx + activation tx in one go |
| `cargo stylus activate --address 0x…` | Activates separately (after `deploy --no-activate`, or to reactivate) |
| `cargo stylus verify` | Reproducible-build check that onchain code matches source |

Useful flags: `--estimate-gas` (price it first), `--no-activate`, `--private-key-path key.txt` (nicer than inline keys), `--constructor-args … --constructor-value …`, `--no-verify` (skip the Docker reproducible build while iterating).

## Activation: the Extra Step vs Solidity

A Solidity deploy is one transaction — bytecode lands and it's callable. Stylus splits this in two:

1. **Deploy** — your WASM (Brotli level 11, `EFF00000` prefix, decompressed size ≤ 128 KB) is stored at an address like any contract.
2. **Activate** — the **ArbWasm precompile (`0x71`)** safety-checks the WASM, instruments it, and compiles it to **native machine code** for validators. Costs a one-off **data fee** in ETH (estimated by simulation; `cargo stylus` bumps the estimate ~20% for safety).

Why: doing that processing once and caching it beats re-processing on every call, and contracts sharing a codehash share the activation. Activation lasts **365 days** (`ExpiryDays`) — check with `ArbWasm.programTimeLeft()`, extend with `codehashKeepalive()`, or reactivate if it lapses (code never disappears; only the activation state does). A Stylus **version upgrade** also requires recompiling with the newer SDK and redeploying.

## Hands-on: Hello World → Sepolia

Local first:

```shell
cargo stylus new hello && cd hello
cargo stylus check --endpoint http://localhost:8547
cargo stylus deploy --endpoint http://localhost:8547 \
  --private-key 0xb6b15c8cb491557369f3c7d2c287b053eb229daa9c22138887752191c9520659

# poke it with cast
cast call --rpc-url http://localhost:8547 <ADDRESS> "number()(uint256)"
cast send --rpc-url http://localhost:8547 --private-key 0xb6b1… <ADDRESS> "increment()"
```

Then the exact same flow against Sepolia — only the endpoint and key change:

```shell
cargo stylus deploy \
  --endpoint https://sepolia-rollup.arbitrum.io/rpc \
  --private-key-path ./key.txt
```

Fund the wallet from a Sepolia faucet + [bridge.arbitrum.io](https://bridge.arbitrum.io) first (same as module 2.4). The deploy output shows both txs — deployment and activation — and the contract address you can check on [sepolia.arbiscan.io](https://sepolia.arbiscan.io).

Unit tests don't need any node at all: add `stylus-sdk` with the `stylus-test` feature and plain `cargo test` runs your contract logic against an in-memory `TestVM`.
