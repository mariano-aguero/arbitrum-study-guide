# 3.1 — Introduction to Stylus

> **TL;DR:** Stylus adds a **second VM (WASM)** next to the EVM on Arbitrum — same chain, same state, contracts in **Rust/C/C++** that interoperate with Solidity in both directions. Compute gets **~10× cheaper** and memory far cheaper still, because WASM runs as native machine code; **storage costs stay the same**. A Stylus contract lives through four stages: **code → activate → execute → prove**. It is *not* a new chain, *not* a Solidity replacement, and *not* a win for storage-bound contracts.

## MultiVM: a Coequal WASM VM Next to the EVM

Stylus shipped with **ArbOS 32** as an upgrade to Nitro — not a new network. One chain, one state trie, two runtimes:

| | **EVM contracts** | **Stylus contracts** |
|---|---|---|
| Written in | Solidity, Vyper | Rust (first-class SDK), C, C++ |
| Deployed as | EVM bytecode | Compressed **WASM** |
| Executed by | Geth (unchanged) | Native code via a **Wasmer** fork |
| Storage / addresses / balance | Same model, same trie | Same model, same trie |

- **Routing is automatic:** when a contract is called, ArbOS checks whether the code is EVM bytecode or a WASM program and dispatches to the right runtime. Callers can't tell the difference.
- **Full interop:** a Solidity contract can call a Rust contract and vice versa — same ABI, same `CALL` semantics, composable in one transaction. EVM contracts keep behaving *exactly* as on Ethereum.

## Lifecycle: Code → Activate → Execute → Prove

1. **Code** — write Rust against the `stylus-sdk`, compile to WASM with `cargo stylus`, deploy the (Brotli-compressed) WASM onchain like any contract.
2. **Activate** — a one-time step via the **ArbWasm precompile**: the WASM is safety-checked, instrumented for metering, and compiled down to **native machine code** for validators. Costs a small data fee. Contracts must be **re-activated every 365 days** or after a Stylus version upgrade (`cargo stylus` handles deploy + activate).
3. **Execute** — calls run the pre-compiled native code. Metering uses **ink**, a sub-unit of gas (1 gas = 10,000 ink) — needed because one EVM opcode takes as long as *thousands* of WASM instructions, so pricing must be finer-grained.
4. **Prove** — in a dispute, the same WASM is run by Nitro's prover and bisected down to a **one-step proof** verified on Ethereum. Nitro already fraud-proves over WASM, which is exactly why adding user WASM was natural.

## Why WASM

- **Cost:** decades of compiler optimization + native execution → compute is ~**10× cheaper** and memory dramatically cheaper than the EVM. A compute-heavy benchmark in the Arbitrum Foundation's backend-engineer guide used **>90% less gas** than the equivalent Solidity.
- **Library reuse:** bring mature ecosystems onchain — Rust crates for crypto, math, data structures — instead of reimplementing them in Solidity. You can even share one typed crate between the contract and your offchain backend.
- **Language support:** Rust is first-class; C/C++ supported; anything that compiles to WASM is possible in principle. Languages that need a heavy runtime (Python, JS) aren't practical.

## Use Cases

| Use case | Why Stylus |
|---|---|
| **ZK / signature verification** | Heavy math that's prohibitive in the EVM (e.g. Renegade verifying ZK proofs) |
| **Custom AMMs & DeFi math** | Exotic pricing curves, options/futures engines, fixed-point math at low cost |
| **Compute-heavy apps** | Games, generative art, simulations, in-memory algorithms |
| **Hybrid contracts** | Keep storage + auth in Solidity, call a Stylus contract for the expensive compute |

## What Stylus is NOT

- **Not a new chain or a fork** — it's an ArbOS feature of Arbitrum chains.
- **Not a Solidity replacement** — the EVM stays; Solidity remains the right tool for most storage-centric contracts.
- **Not cheaper storage** — `SLOAD`/`SSTORE` cost the same as in the EVM, so storage-heavy contracts gain little by porting. Port the *compute*, not the token.
- **Not a general-purpose server** — still onchain: deterministic (no floats, no clock, no network), metered, `no_std` Rust.
