# 3.2 — Rust for Smart Contracts

> **TL;DR:** You don't need *all* of Rust for Stylus — you need the **strict minimum**: ownership/borrowing (the borrow checker), traits + generics, and `Result`-based error handling. Toolchain-wise it's **rustup + cargo** plus the `wasm32` target. The big constraint is **`no_std`**: contracts run without the standard library (no files, threads, clock, floats), with only `alloc` for heap types. If you already know a typed language, follow the skip-points table below instead of reading the Book cover to cover.

## Toolchain: rustup, cargo, edition, MSRV

| Tool / concept | What it is |
|---|---|
| **rustup** | Installs and manages Rust toolchains *and compile targets*. Stylus needs `rustup target add wasm32-unknown-unknown`. |
| **cargo** | Build tool + package manager (crates, `Cargo.toml`, `cargo build/test/run`). `cargo stylus` plugs into it. |
| **edition** | Per-crate language "era" (2015/2018/2021/2024). Opt-in, all editions interoperate — set it in `Cargo.toml` and forget it. |
| **MSRV** | *Minimum Supported Rust Version* — the oldest compiler a crate promises to build with. The `stylus-sdk` pins one; a `rust-toolchain.toml` in your repo keeps everyone (and CI) on the same version. |

## Ownership, Borrowing, Lifetimes (strict minimum)

The borrow checker enforces memory safety at compile time — no GC, no runtime cost. The three rules that cover 90% of what you'll hit:

1. **One owner:** every value has exactly one owner; assignment/passing **moves** it (the old binding is dead). Types like `u64` are `Copy` and duplicate instead.
2. **Borrow, don't move:** `&T` = shared read-only reference (many at once), `&mut T` = exclusive mutable reference (only one, and no readers while it lives). *Aliasing XOR mutability.*
3. **Lifetimes are mostly inferred:** you'll rarely write `'a` in contract code. When the compiler asks for one, it's telling you a reference could outlive its data — restructure instead of fighting it.

Why it matters for Stylus: the SDK models storage access with these same rules — getting a mutable handle to a storage field borrows the contract state, so the compiler stops you from aliasing storage the way reentrancy-prone Solidity can.

## Traits, Generics, Error Handling

- **Traits** = interfaces the type opts into (`impl Trait for Type`). You'll mostly *derive* them: `#[derive(Debug, Clone, PartialEq)]`. The SDK's macros (`#[entrypoint]`, `sol_storage!`) generate trait impls for you.
- **Generics** are **monomorphized** — the compiler stamps out one copy per concrete type. Zero runtime cost, but each instantiation adds bytes, and your compressed WASM must fit the **24 KB onchain size limit** — keep contract generics modest.
- **Errors are values:** fallible functions return `Result<T, E>`; the `?` operator propagates the `Err` upward. No exceptions. A `panic!` in a contract aborts execution → the tx **reverts**, so prefer typed `Err`s for expected failures. [`thiserror`](https://docs.rs/thiserror) gives ergonomic error enums in shared/offchain crates; onchain, the SDK ABI-encodes error types so Solidity callers see normal custom errors.

## `no_std`: the Embedded Constraints of Stylus

A contract is closer to firmware than to a backend service. `#![no_std]` means no OS facilities at all — only `core` plus **`alloc`** (heap types):

| Habit from backend Rust | Onchain reality |
|---|---|
| `std::fs`, `std::net`, `std::thread` | Don't exist — no files, network or threads |
| `SystemTime::now()`, `rand` | Non-deterministic → forbidden; use `block.timestamp` / commit-reveal |
| `f32`/`f64` floats | Non-deterministic across platforms → use fixed-point (e.g. `I40F24`) or integer math |
| `println!`, loggers | Emit **events** instead |
| Any crate you like | Dependencies must be `no_std`-compatible and WASM-friendly |

`Vec`, `String`, `Box`, `BTreeMap` still work (they come from `alloc`). Determinism is the theme: same inputs, same outputs, on every validator.

## Curated Learning Path (with skip points)

| You are… | Do this |
|---|---|
| **New to Rust** | The Book ch. 1–10 in order, doing [rustlings](https://github.com/rust-lang/rustlings) alongside each chapter; then jump to Stylus examples |
| **Senior dev (TS/Go/Java…)** | Skim ch. 1–3 fast, **read ch. 4 (ownership) carefully — it's the only genuinely new idea**, then ch. 9 (errors) and ch. 10 (traits/generics/lifetimes). Skip the rest until needed |
| **Prefer guided video** | [Cyfrin Updraft's Rust Programming Basics](https://updraft.cyfrin.io/courses/rust-programming-basics) — web3-oriented from the start |
| **Learn by reading code** | [Rust by Example](https://doc.rust-lang.org/rust-by-example/) as a snippet reference while writing your first contract |

Whatever the path, the checkpoint is the same: you can explain *why a value moved*, write a function returning `Result` with `?`, and implement a trait — that's enough Rust to start Module 3.3.
