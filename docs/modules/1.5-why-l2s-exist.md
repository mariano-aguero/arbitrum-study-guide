# 1.5 — Why L2s Exist

> **TL;DR:** Ethereum does ~15 TPS and fees explode under load, so its roadmap bets on rollups: execute transactions off-chain, post compressed data to L1, inherit its security. Optimistic rollups (Arbitrum, Optimism/Base) assume validity and allow fraud proofs; ZK rollups prove every batch cryptographically. Arbitrum is the largest optimistic rollup.

## Why Do L2s Exist?

Ethereum L1 processes **~15 transactions per second**, and under demand spikes fees have hit tens of dollars per transfer — unusable for most applications. So why not just make L1 faster? Every obvious alternative gives something up:

- **Bigger/faster blocks** → running a node gets expensive → fewer validators → **centralization**. This is the **trilemma**: scalability, security, decentralization — you can't max all three at one layer.
- **Sidechains** (own consensus) and **alt-L1s** → scale fine, but **you give up Ethereum's security** and fragment liquidity.
- **L2s are the way out of the trade-off**: move *execution* to another layer, but **anchor security to Ethereum** — every L2 batch is settled and verifiable on L1. You get low fees and high throughput *without* trusting a new validator set.

**In one line: L2s exist to scale Ethereum without sacrificing its security or decentralization.**

## The Rollup-Centric Roadmap

- Ethereum's official strategy embraces this: instead of scaling execution on L1 (sharding was deprioritized), L1 focuses on **security + data availability** (Danksharding path) and pushes execution to L2s — the **rollup-centric roadmap**.
- **A rollup**: executes txs off-chain → compresses them into batches → posts data + a state root to Ethereum. L2 provides throughput, L1 provides security and a place to settle disputes.

## Optimistic vs ZK Rollups

| | **Optimistic** | **ZK** |
|---|---|---|
| Validity | Assumed honest; anyone can submit a **fraud proof** during a challenge window (~7 days) | **Validity proof** (cryptographic) posted with every batch |
| Withdrawal to L1 | ~7 days (challenge window)* | Near-instant once proof verifies |
| EVM compatibility | Full equivalence — deploy unchanged | Historically hard, gap closing (zkEVMs) |
| Cost profile | Cheap to operate; pay only when disputed | Proof generation is compute-heavy |
| Examples | **Arbitrum**, Optimism, Base | zkSync, Scroll, Linea, Starknet |

\* In practice, bridges/liquidity providers front the funds so users rarely wait the full window.

## Data Availability, Sequencers, Fraud Proofs

- **Data availability (DA):** the rollup's tx data must be *published* somewhere anyone can read, or nobody can reconstruct state / challenge fraud. Posting to Ethereum = full L1 security. **EIP-4844 blobs** (2024) cut rollup posting costs by ~90%+. Validiums store data off-chain — cheaper, weaker guarantees.
- **Sequencer:** orders and executes txs, gives instant "soft confirmations". Today most rollups run a **single sequencer operated by the team** — a centralization point (ordering, MEV, censorship). Mitigation: users can usually force-include txs via L1; decentralized sequencing is on every roadmap.
- **Fraud proofs:** in optimistic rollups, a posted state root can be challenged; an interactive dispute game re-executes the contested step on L1 and slashes the liar. One honest verifier is enough to keep the chain honest.

## The L2 Landscape & Where Arbitrum Sits

- **Optimistic camp:** **Arbitrum One** (largest L2 by TVL), OP Stack chains (Optimism, Base).
- **ZK camp:** zkSync Era, Starknet, Scroll, Linea, Polygon zkEVM.
- **Not rollups:** sidechains (Polygon PoS — own consensus, doesn't inherit L1 security), state channels, validiums.
- **Arbitrum specifics:** optimistic rollup with the **Nitro** stack; **BoLD** brings permissionless validation; **Orbit** lets anyone launch their own L3/L2 chain; **Stylus** adds Rust/WASM contracts alongside the EVM — the subject of this fellowship.
