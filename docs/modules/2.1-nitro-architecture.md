# 2.1 — Nitro Architecture

> **TL;DR:** Nitro is the stack that runs Arbitrum One. A **sequencer** orders your txs and gives instant *soft* confirmations; a forked **Geth** executes them (so it's EVM-equivalent); the batched txs are **compressed and posted to Ethereum L1**, where they get *hard* finality. **ArbOS** is the L2 operating system that sits on top and is the unit that gets upgraded. If the sequencer censors you, the **delayed inbox** lets you force your tx in through L1.

## Nitro Internals

Nitro's execution is a **"Geth sandwich"** — three layers:

| Layer | What it does |
|---|---|
| **Geth (core)** | A lightly forked Ethereum client. Runs the EVM, so contracts behave exactly like L1 → full EVM equivalence. |
| **ArbOS** | The L2 "operating system": decompresses sequencer data, meters L1+L2 gas, handles cross-chain messaging and fees. |
| **Node interface** | The RPC surface dapps and wallets talk to. |

- **Sequencer** — orders incoming transactions (first-come, first-served) and broadcasts them on a real-time **feed**. Today it's a single operator (Offchain Labs); decentralizing it is on the roadmap.
- **Calldata compression** — before posting to L1, batches are compressed with **Brotli** (level adjusts with congestion). Data goes to Ethereum as **EIP-4844 blobs** (or calldata), cutting L1 costs ~10–100×. Posting data to L1 is what makes the rollup verifiable.
- **State Transition Function (STF)** — the deterministic rule "state + txs → new state": ArbOS validates and charges gas, Geth executes per the EVM, ArbOS commits the new state. Everyone re-running it gets the same result.

## Soft vs Hard Finality & Censorship Resistance

Two levels of "is my tx final?":

| | **Soft finality** | **Hard finality** |
|---|---|---|
| When | Instant, on sequencer inclusion | ~10–20 min, when the batch is posted and Ethereum confirms it |
| Backed by | The sequencer's promise (trust) | Ethereum's consensus (cryptographic) |
| Good for | Snappy UX, instant feedback | Settlement, bridging out, anything final |

- The instant confirmation you feel in a wallet is **soft** — fast, but only as trustworthy as the sequencer.
- **Censorship-resistant inclusion:** if the sequencer ignores or censors your tx, you can submit it directly to the **Delayed Inbox** contract on L1. After a delay (~24h) you can **force-include** it, so the sequencer can't keep you out forever. This is what keeps a centralized sequencer honest.

## ArbOS as the Upgrade Unit

- **ArbOS** is the L2 system software (think "the OS of the chain") that runs *on top of* Nitro: gas accounting for both L1 data and L2 execution, the cross-chain message bridge, batch decompression, and chain configuration.
- Crucially, it's the **unit of upgrade**: Arbitrum ships new features by bumping the **ArbOS version** (e.g. new opcodes, fee-model tweaks, Stylus support) rather than doing a disruptive hard fork of the whole chain. Upgrades are governance-gated.
- This is why "ArbOS 32 / Dia" style version names matter — the ArbOS version tells you which features and pricing rules a given Arbitrum chain is running.
