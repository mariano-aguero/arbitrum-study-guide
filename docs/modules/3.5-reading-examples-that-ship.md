# 3.5 — Reading Examples That Ship

> **TL;DR:** After the SDK theory, calibrate against real code from three sources with different altitudes: **Stylus by Example** for isolated patterns (start with the 5 below), the **stylus-sdk-rs repo** to read what the macros actually expand to, and **Awesome Stylus** to see what production teams (Renegade, Superposition) ship. The goal of this module is the Week 3 outcome: reading SDK macros **without consulting the docs for every line**.

## Stylus by Example: 5 Patterns Worth Walking Through

[stylus-by-example.org](https://stylus-by-example.org/) is organized as ~24 basic examples plus 7 small applications. Don't read it linearly — walk these five, in order, and ask of each "how would I have written this in Solidity?":

| Pattern | What it teaches |
|---|---|
| **Events** | Alloy's `sol!` for event types + `log()` — the Solidity `emit` equivalent |
| **Mappings** | `StorageMap` access via `.getter()`/`.setter()`, nested mappings, and why the guard types exist |
| **Errors** | Typed error enums with `SolidityError` → real custom errors an EVM caller can decode |
| **ERC-20** | A full token: storage struct, `#[public]` interface, events and errors together — compare it line-by-line with OpenZeppelin's Solidity ERC-20 |
| **Vending Machine** (or **Multicall**) | A small complete app: payable methods, ether handling, state transitions |

Each example is a self-contained crate — clone it, `cargo stylus check` it against your devnode from module 3.4, break it, redeploy it.

## stylus-sdk-rs Source as a Learning Surface

The SDK repo ([v0.10.x](https://github.com/OffchainLabs/stylus-sdk-rs)) is small enough to read, and it answers the "what does this macro actually do?" questions the docs gloss over:

- **`examples/`** — official example contracts, kept compiling against the current SDK (unlike random blog posts).
- **`stylus-proc/`** — the proc macros. Reading how `#[public]` builds the router or what `sol_storage!` generates demystifies the "magic"; `cargo expand` on your own contract shows the generated code directly.
- **`stylus-sdk/src/storage/`** — the storage types and cache. This is where the slot layout equivalence with Solidity is implemented.
- **`stylus-test/`** — the `TestVM`; skim it once and unit-testing contracts stops feeling like a black box.

Reading tactic: pick one `#[public]` method in an example, expand it, and follow the call into the SDK until you hit a host function. One pass of that beats hours of docs.

## Awesome Stylus: Community-Vetted Projects

[awesome-stylus](https://github.com/OffchainLabs/awesome-stylus) is the curated index — guides, videos, tooling, libraries and, most usefully, **production code**:

- **[Renegade](https://renegade.fi)** — onchain dark pool using ZK proofs; the flagship "compute too heavy for the EVM" case from module 3.1, in production.
- **Superposition Longtail** — an AMM built with Stylus on an Orbit L3 — the "custom AMM math" use case, shipped.
- **OpenZeppelin Contracts for Stylus** — the audited ERC-20/721/1155 + access-control building blocks from module 3.3.
- **Rustmate** — optimized Rust building blocks (the Solmate analogue for Stylus).

When evaluating anything from the list, check which **SDK version** it targets — pre-0.10 code won't compile against the current SDK, though the patterns still read fine.
