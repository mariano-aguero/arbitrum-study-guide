# 1.3 — Dev Environment & Tooling

> **TL;DR:** Foundry for contracts (fast, Solidity-native tests, `anvil` for local/forked nodes), Hardhat when the workflow is JS/TS-heavy. On the frontend, viem + wagmi is the modern typed stack; wallets connect via injected (MetaMask), WalletConnect or a kit like RainbowKit. Account abstraction (ERC-4337 + EIP-7702) is turning wallets into programmable smart accounts.

## Hardhat vs Foundry

| | **Foundry** | **Hardhat** |
|---|---|---|
| Tests written in | Solidity | JavaScript/TypeScript |
| Speed | Very fast (Rust) | Slower (Node) |
| Fuzzing / invariants | Built-in | Via plugins |
| Ecosystem | `forge`, `cast`, `anvil`, `chisel` | Rich plugin ecosystem, viem/ethers integration |
| Pick it when… | Contract-centric work, fuzz/invariant testing, quick CLI txs | Full-stack JS/TS projects, custom deploy scripts, teams that live in TS |

They're not exclusive — many teams use Foundry for testing and Hardhat for deployment tooling.

```bash
# Foundry in 30 seconds
forge init my-project   # scaffold
forge test              # run Solidity tests
cast call <addr> "balanceOf(address)" <who>   # poke any contract from the CLI
```

## Local Nodes & Mainnet Forking

- **`anvil`** (Foundry) or **`npx hardhat node`** spin up a local chain with funded accounts — instant blocks, zero cost.
- **Forking** copies mainnet state into your local node, so you test against *real* contracts (Uniswap, USDC…) without spending real ETH:

```bash
anvil --fork-url $MAINNET_RPC_URL          # local mainnet clone
forge test --fork-url $MAINNET_RPC_URL     # tests against forked state
```

- Cheatcodes make forked tests powerful: `vm.prank(whale)` to impersonate any address, `vm.deal(me, 100 ether)` to mint yourself ETH, `vm.warp()` to time-travel.

## JSON-RPC & Frontend: viem + wagmi

Everything talks to a node via **JSON-RPC** (`eth_call`, `eth_sendRawTransaction`, `eth_getLogs`…). Libraries wrap it:

- **viem** — modern TypeScript client (replaces ethers): typed contract calls, `parseUnits`/`formatUnits` (never do float math with token amounts).
- **wagmi** — React hooks on top of viem + TanStack Query. Key patterns:
  - Define ABIs `as const` → full type inference, typos caught at compile time.
  - **Reads:** `useReadContract` (single) / `useReadContracts` (batched multicall in one RPC round-trip).
  - **Writes are 2 phases:** `useWriteContract` (user signs) → `useWaitForTransactionReceipt` (tx mined). Wire UI to `isPending` → `isConfirming` → `isConfirmed`.
  - **Errors:** use `error.walk()` to tell user-rejections from reverts; show `error.shortMessage`.
  - **Wrong network?** `useSwitchChain` switches (or adds) the chain in the wallet.
- **ethers** — the predecessor; still everywhere in older codebases, know how to read it.

## Wallets

- **MetaMask** — the standard *injected* wallet (`window.ethereum`); holds keys, signs txs.
- **WalletConnect** — open protocol to link dapps with mobile/hardware wallets via QR code — not a wallet itself.
- **RainbowKit** — drop-in React "Connect Wallet" UI on top of wagmi that bundles injected + WalletConnect + more, so you don't hand-roll the modal.

## Account Abstraction Primer (ERC-4337 & EIP-7702)

Classic EOAs are rigid: one private key, lose it = lose everything, every tx needs ETH for gas. **Account abstraction** makes accounts programmable smart contracts.

- **ERC-4337** (2023, no protocol change) — the infrastructure layer:
  - **UserOperation** — a signed intent (instead of a raw tx)
  - **Bundler** — packages UserOps into regular transactions
  - **EntryPoint** — singleton contract that validates & executes them
  - **Paymaster** — sponsors gas, so users can pay in tokens or nothing at all
- **EIP-7702** (Pectra upgrade, 2025) — protocol-level: an EOA can *temporarily delegate* to contract code within a transaction — your existing address gets smart-account powers without migrating.
- They complement each other: 4337 provides the rails (bundlers/paymasters), 7702 lets plain EOAs plug into them.
- **What it unlocks for UX:** gasless txs (sponsored), batching (approve + swap in one click), session keys (limited, time-bound signing), recovery via guardians instead of seed phrases.
